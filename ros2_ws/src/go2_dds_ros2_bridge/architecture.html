GO2 · ROS2 · FAST-LIO

Navigation and CBF architecture

A single launch connects the robot or simulator to mapping, a four-frame LiDAR navigation policy, and an optional world-frame CBF. With CBF enabled, navigation proposes a velocity and the CBF publishes the robot command.

01 · Mapping foundation

From DDS to a localized robot

Hardware and simulate_python use the same DDS bridge. FAST-LIO provides odometry and the map frame used by navigation and CBF.

Static mode

cbf_mode: static uses the world scan with zero obstacle velocity. The predictor node is idle.

Dynamic mode

cbf_mode: dynamic uses a four-frame predictor. It rotates predicted velocities into cbf_world and advances held front points to evaluation time.

Predictor unavailable

The controller uses a fresh static snapshot and reports the reason on /cbf/status. If static inputs also fail, it follows its hold-then-stop path.

Switching modes

Set cbf_mode in cbf_control.yaml and restart. Dynamic mode also needs a four-frame temporal_lidar_v4 JIT path.

The checked-in four-frame predictor declares temporal_lidar_v3, so the new dynamic node rejects it and the controller uses static fallback until a validated v4 artifact is configured.
